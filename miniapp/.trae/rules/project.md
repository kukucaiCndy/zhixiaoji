## 强制要求

1. **上下文加载**：每次都需要在上下文中加载 `project.md`。

2. **意图确认**：每次接受到任务后，都需要仔细分析用户意图。如果有不理解或者认为意图模糊的时候，必须反问用户，确认好意图后再执行。

3. **Agent 协同**：执行任务要在当前合适的 Agent 配置中选取 Agent 调用。如果能同时协同多个 Agent，则协同调用多个 Agent 完成任务，提升任务效率。

4. **Git 本地提交**：每次修改都需要维护 git 仓库，提交代码修改记录到本地仓库。

5. **禁止擅自推送远程**：用户未主动要求，不得擅自提交到远程仓库。

## 核心原则

这是一个纯粹的前端项目。在遇到调用后端问题后，需要严格按照后端 SDK 文档进行调用。如果发现后端 SDK 有问题，则直接返回问题原因在后端。**不要尝试去强行改变前端业务逻辑来适配后端**。

> **举例**：后端 SDK 文档中对某个 API 的定义与后端提供的 SDK 实际不符合时，需要坚持以文档为主，不得直接使用后端 SDK 中提供的不符合规范的 SDK。

你只负责你当前工作目录下的文件修改；你只能读取，但不得修改上级工作目录下的其它文件夹中的内容。
