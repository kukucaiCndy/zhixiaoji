本文档为「知晓记」微信小程序的产品需求规格说明书，旨在明确产品定位、目标用户、核心功能、业务流程及非功能需求，为后续UI/UX设计、技术选型、开发实现及测试验收提供基准依据。

| 术语 | 定义 |

## 二、产品概述

### 2.1 产品名称

**知晓记** —— "知晓"寓意掌握知识、了解原理，"记"既代表记录学习笔记，也暗含记忆强化的产品特色。

### 2.2 产品定位

> **帮助AI编程学习者，以最低的学习门槛，快速掌握计算机基础知识和软件开发基本原理，从而更好地驾驭AI工具完成软件开发。**

知晓记定位于**AI时代的编程启蒙教育工具**，不是培养专业程序员，而是帮助非技术背景的用户建立足够的"技术认知基础"，使其能够：
- 理解AI给出的代码和建议
- 知道如何向AI提出有效的编程问题
- 具备判断AI输出质量的基本能力
- 了解软件开发的完整流程和基本概念

### 2.3 产品Slogan

> **先知晓，再编程 —— 让AI成为你的得力助手**

### 2.4 核心价值主张

| 维度 | 价值描述 |
|------|----------|
| **低门槛** | 零基础友好，用通俗语言解释技术概念，避免专业术语堆砌 |
| **碎片化** | 利用碎片时间学习，每次5-10分钟即可完成一个知识单元 |
| **系统化** | 从计算机基础到软件开发全流程，构建完整的知识框架 |
| **强互动** | 学练结合，通过刷题和记忆强化巩固学习效果 |
| **可验证** | 积分体系和进度追踪，让学习成果可视化 |

## 三、目标用户分析

### 3.1 核心用户画像

#### 画像一：产品/运营转行者（主力用户）
- **基本信息**：25-35岁，产品经理、运营、市场等非技术岗位
- **学习动机**：希望借助AI工具自主开发产品原型、自动化工具，或转型技术相关岗位
- **能力现状**：对编程有模糊认知，知道一些术语但不理解原理，没有系统学习过计算机科学
- **痛点**：
  - 使用AI编程时，看不懂AI生成的代码
  - 不知道如何让AI更好地理解自己的需求
  - 遇到报错无从下手，只能反复问AI
  - 缺乏基础知识导致学习效率极低
- **使用场景**：通勤路上、午休时间、睡前等碎片时段学习

#### 画像二：传统行业技术人员
- **基本信息**：30-45岁，从事硬件、网络、运维等技术工作，但非软件开发
- **学习动机**：希望扩展技能边界，利用AI提升工作效率，或开发内部工具
- **能力现状**：具备一定的逻辑思维和技术基础，但对软件开发流程、编程语言不熟悉
- **痛点**：
  - 有一定技术背景但缺乏软件工程思维
  - 不知道软件开发的标准流程和最佳实践
  - 需要系统性地补齐知识短板

#### 画像三：AI工具爱好者
- **基本信息**：20-40岁，对AI技术充满兴趣，希望深度使用AI工具
- **学习动机**：不满足于表面使用AI，希望理解底层原理，成为"AI驾驭者"
- **能力现状**：可能是设计师、自媒体从业者、自由职业者等，学习能力较强但缺乏技术基础
- **痛点**：
  - 被AI的"幻觉"误导，无法辨别正确与错误的输出
  - 想要定制化使用AI但缺乏必要的技术知识
  - 学习资源分散，缺乏针对AI使用者的系统化课程

### 4.2 模块一：笔记管理

#### 4.2.1 功能概述

为用户提供个人知识管理空间，支持在学习过程中随时记录心得、整理知识、建立个人知识体系。笔记可与学习内容关联，形成"学习-记录-复习"的闭环。

#### 4.2.2 用户故事

- **US-NOTE-01**：作为学习者，我希望在学习过程中快速记录笔记，以便日后复习
- **US-NOTE-02**：作为学习者，我希望对笔记进行分类管理，以便有条理地整理知识
- **US-NOTE-03**：作为学习者，我希望笔记能关联到具体的知识点，以便追溯学习上下文
- **US-NOTE-04**：作为学习者，我希望能够搜索历史笔记，以便快速找到需要的内容

#### 4.2.3 功能详述

##### 4.2.3.1 新建笔记

| 属性 | 说明 |
|------|------|
| **功能入口** | 全局悬浮"记笔记"按钮（始终可见）/ 学习页面内嵌"记笔记"按钮 |
| **触发条件** | 用户主动点击，随时可记录 |
| **笔记标题** | 自动生成默认标题：`{当前知识点名称} {YYYY-MM-DD HH:mm}`，用户可修改 |
| **输入内容** | 笔记正文（必填，最多5000字） |
| **关联知识点** | **自动必填**，根据用户当前学习上下文自动绑定 |
| **上下文记录** | 自动记录当前学习内容类型（文字/图文/视频）及对应内容片段 |
| **富文本支持** | 支持文字、图片（拍照/相册）、代码块、引用格式 |
| **保存规则** | 自动保存草稿，手动确认后正式保存 |

##### 4.2.3.2 上下文关联机制

- **文字内容**：自动记录当前阅读的文字段落摘要，笔记详情页可一键跳转至原文位置
- **图文内容**：自动关联当前图文卡片，笔记中可查看缩略图，点击跳转至完整图文
- **视频内容**（未来支持）：自动记录当前视频播放时间点，笔记可跳转至对应视频帧
- **双向追溯**：在笔记详情页可查看关联的学习上下文；在学习内容页可查看所有关联笔记

##### 4.2.3.3 笔记审核机制

| 审核环节 | 说明 |
|----------|------|
| **自动审核** | 笔记提交后先经过敏感词过滤和AI内容安全检测 |
| **人工复核** | 对疑似违规内容进行人工复核（24小时内完成） |
| **审核状态** | 待审核 / 审核通过 / 审核未通过（含原因） |
| **未通过处理** | 用户可修改后重新提交审核 |

**审核影响**：
- **审核通过前**：笔记仅自己可见，不可分享/转发
- **审核通过后**：笔记可正常分享、转发、被他人查看（如设为公开）
- **审核未通过**：笔记退回草稿状态，提示修改建议

#### 4.2.3.4 编辑与删除笔记

- 支持对已创建笔记进行全量编辑（标题、正文、标签）
- **关联知识点不可修改**，确保笔记与学习内容的绑定关系
- 支持删除笔记，删除前二次确认
- 显示笔记创建时间和最后修改时间
- **重新编辑后需重新审核**：已审核通过的笔记编辑后，状态变为"待审核"，需再次审核通过方可分享

##### 4.2.3.5 笔记分类

| 分类维度 | 说明 |
|----------|------|
| **系统分类** | 按知识领域自动分类（计算机基础、编程语言、Web开发、数据库、AI基础等） |
| **自定义标签** | 用户可创建自定义标签，单篇笔记可打多个标签 |
| **时间维度** | 按创建时间自动归档（本周、本月、更早） |
| **内容类型** | 按关联内容类型分类（文字笔记/图文笔记/视频笔记） |
| **审核状态** | 按审核状态筛选（待审核/已通过/未通过） |

##### 4.2.3.6 笔记搜索

- 支持按关键词搜索笔记标题和内容
- 支持按标签筛选
- 支持按时间范围筛选
- 支持按关联知识点筛选
- 支持按内容类型筛选
- 支持按审核状态筛选
- 搜索结果按相关性和时间排序

##### 4.2.3.7 笔记关联

- 笔记**强制关联**一个知识点，作为学习上下文的锚点
- 在知识卡片详情页可查看所有关联的笔记列表（仅显示审核通过的公开笔记）
- 在笔记详情页可跳转至关联的知识卡片及对应上下文位置

#### 4.2.4 页面原型说明

**笔记列表页**
- 顶部：搜索栏 + 分类筛选标签
- 中部：笔记列表（卡片式布局，显示标题、摘要、关联知识点、时间）
- 底部：新建笔记浮动按钮

**笔记详情页**
- 顶部：标题 + 编辑/删除按钮
- 中部：笔记内容（富文本渲染）
- 底部：关联知识点入口、时间信息

**笔记编辑页**
- 顶部：标题输入框
- 中部：富文本编辑器（工具栏：文字样式、图片、代码块、引用）
- 底部：关联知识点选择器、保存按钮

#### 4.3.3 知识卡片学习

##### 4.3.3.1 功能概述

将知识点拆分为一张张独立的"知识卡片"，每张卡片聚焦一个核心概念，采用"概念解释 + 生活类比 + 代码示例 + 要点总结"的结构，确保零基础用户能够理解。

##### 4.3.3.2 卡片内容结构

| 元素 | 说明 | 必填 |
|------|------|------|
| **卡片标题** | 知识点名称，简洁明了 | 是 |
| **难度标签** | 入门/基础/进阶 | 是 |
| **预计学习时长** | 建议学习时间（分钟） | 是 |
| **概念解释** | 用通俗语言解释概念，避免专业术语 | 是 |
| **生活类比** | 用日常生活场景类比技术概念 | 是 |
| **代码示例** | 简洁的代码片段（如有必要） | 否 |
| **图解说明** | 示意图、流程图等可视化内容 | 否 |
| **要点总结** | 3-5个核心要点提炼 | 是 |
| **延伸阅读** | 关联知识卡片推荐 | 否 |
| **互动提问** | 引导用户思考的简单问题 | 否 |

##### 4.3.3.3 卡片学习流程

```
开始学习
    │
    ▼
┌─────────────┐
│  卡片正面    │  ← 显示概念问题或核心概念标题
│  （引导思考） │
└─────────────┘
    │ 用户点击"查看解释"
    ▼
┌─────────────┐
│  卡片背面    │  ← 显示完整解释、类比、示例
│  （详细内容） │
└─────────────┘
    │
    ├── 点击"理解了" → 标记为已学习，进入下一章/推荐测验
    ├── 点击"有点难" → 加入"需复习"列表，推荐重学或测验巩固
    └── 点击"记笔记" → 跳转笔记编辑页，自动关联本卡片
```

> **积分规则**：卡片学习过程**不产出积分**，积分仅通过后续测验/考试通过获得。学习是积累知识的过程，测验是验证学习成果并获得奖励的环节。

##### 4.3.3.4 学习路径设计

| 路径类型 | 说明 |
|----------|------|
| **主线路径** | 按知识体系顺序学习，适合系统学习的用户 |

| **兴趣路径** | 用户自选感兴趣的章节，自由探索 |
| **补弱路径** | 根据刷题错误情况，推荐薄弱知识点 |

#### 4.3.4 刷题学习

##### 4.3.4.1 功能概述

通过互动式题目检验学习效果，题目类型包括单选题、多选题、判断题，内容紧扣知识卡片知识点，帮助用户巩固记忆、发现薄弱点。

##### 4.3.4.2 题目类型

| 题型 | 说明 | 占比 |
|------|------|------|
| **单选题** | 4个选项，选择唯一正确答案 | 40% |

##### 4.3.4.3 题目内容设计原则

- 每道题目对应一个或多个知识卡片
- 选项设计具有迷惑性，避免一眼看出答案
- 答错后显示解析，解析关联到对应知识卡片
- 题目难度与知识卡片难度匹配

##### 4.3.4.4 刷题模式

| 模式 | 说明 |
|------|------|
| **章节练习** | 针对特定章节的专项练习 |
| **随机练习** | 从已学内容中随机抽题 |
| **错题重练** | 专门针对历史错题的练习 |
| **每日挑战** | 每日10题，连续答对有额外积分奖励 |
| **模拟测验** | 综合测试，检验阶段性学习成果 |

##### 4.3.4.5 答题流程

```
开始答题
    │
    ▼
显示题目 + 选项
    │
    ├── 用户选择答案
    │       │
    │       ▼
    ├─ 正确 → 显示"答对了"+简要解析+获得积分
    │             │
    │             ▼
    │       进入下一题
    │
    └─ 错误 → 显示"答错了"+详细解析+关联知识点卡片入口
```

### 4.4 模块三：记忆强化

#### 4.4.1 功能概述

基于艾宾浩斯遗忘曲线原理，为用户设计科学的复习计划，在最佳时间点提醒用户复习已学内容，将短期记忆转化为长期记忆。

#### 4.4.2 核心机制

##### 4.4.2.1 艾宾浩斯复习节点（用户可配置）

复习节点配置开放给用户，用户可根据自身记忆习惯在小程序端自定义复习间隔。

**默认配置（系统推荐）**：

| 复习次数 | 间隔时间 | 触发条件 |
|----------|----------|----------|
| 第1次复习 | 学习后1天 | 首次学习24小时后 |
| 第2次复习 | 学习后2天 | 第1次复习2天后 |
| 第3次复习 | 学习后4天 | 第2次复习4天后 |
| 第4次复习 | 学习后7天 | 第3次复习7天后 |
| 第5次复习 | 学习后15天 | 第4次复习15天后 |

**用户自定义配置**：

| 配置项 | 可调整范围 | 默认值 |
|--------|------------|--------|
| **第1次复习间隔** | 1-7天 | 1天 |
| **第2次复习间隔** | 1-7天 | 2天 |
| **第3次复习间隔** | 2-14天 | 4天 |
| **第4次复习间隔** | 3-21天 | 7天 |
| **第5次复习间隔** | 7-30天 | 15天 |
| **复习提醒时间** | 任意时间 | 09:00 |
| **周末是否复习** | 是/否 | 是 |

> **配置入口**：我的 → 设置 → 复习计划设置

##### 4.4.2.2 个性化调整

系统根据用户的复习表现动态调整复习间隔：
- **掌握良好**（连续2次快速正确回答）：延长下次复习间隔
- **掌握一般**（答题有犹豫或错误）：保持标准复习间隔
- **掌握较差**（多次错误）：缩短复习间隔，增加复习频次

#### 4.4.3 功能详述

##### 4.4.3.1 智能复习提醒

- **今日复习**：首页显著位置显示"今日待复习"数量
- **复习内容**：包括知识卡片回顾和错题重练
- **复习方式**：
  - 卡片回顾：快速浏览卡片要点，自我检测是否记得
  - 快速测验：针对卡片内容的1-2道测试题
- **完成奖励**：完成当日全部复习任务，增加文具掉落概率10%（当日有效）

##### 4.4.3.2 遗忘预警

- 对即将到达复习节点但尚未复习的内容进行预警标记
- 超过复习节点3天未复习的内容标记为"急需复习"
- 通过服务通知推送复习提醒（需用户授权）

##### 4.4.3.3 复习统计

| 统计项 | 说明 |
|--------|------|
| 记忆持久度 | 综合计算用户对各知识点的掌握程度 |
| 复习完成率 | 计划复习任务中已完成的比例 |
| 记忆曲线图 | 可视化展示知识留存率变化趋势 |
| 薄弱知识点 | 根据复习表现识别出的薄弱知识领域 |

##### 4.4.3.4 复习日历

- 以月历形式展示每日复习任务
- 不同颜色标识：已完成、待复习、已逾期
- 点击日期查看当日具体复习内容

### 4.5 模块四：积分与文具系统

#### 4.5.1 系统概述

建立"学习-奖励-广告-解锁"的良性循环体系：
- **学习行为** → 奖励**文具**（随机掉落，可收集展示）
- **观看广告** → 获得**积分**（唯一获取途径）
- **积分消耗** → **解锁知识内容**（章节/项目/特权）

> **核心设计理念**：
> - 学习本身不直接产生积分，避免功利化学习
> - 文具作为学习行为的正向反馈，满足收集欲和成就感
> - 积分的唯一作用是解锁内容，用户需要观看广告来获取
> - 形成"学习获得成就感 → 想看更多内容 → 主动看广告解锁"的闭环

#### 4.5.2 积分系统

##### 4.5.2.1 积分获取

| 获取方式 | 积分奖励 | 每日上限 | 说明 |
|----------|----------|----------|------|
| **每日登录** | +10积分/天 | 10积分 | 每日首次登录自动获得 |
| **章节测验通过** | +20积分/章 | 60积分 | 正确率≥60%即可获得 |
| **每日挑战完成** | +15积分 | 15积分 | 完成当日10题挑战 |
| **连续打卡7天** | +50积分 | 50积分 | 连续7天登录学习 |
| **观看激励视频广告** | +30积分/次 | 150积分（5次） | 主动点击观看完整视频 |
| **邀请新用户** | +100积分/人 | 500积分 | 被邀请人完成首次学习 |

> **设计原则**：
> - 积分可通过**登录**和**学习考核**获得，鼓励持续学习
> - 观看广告获得积分效率更高，为愿意看广告的用户提供捷径
> - 形成"学习获得积分 → 用积分解锁 → 积分不足可选择看广告"的循环

| **第3人** | 限定道具「知识传递者徽章」+ 100积分 | 累计邀请3人奖励 |
| **第5人** | 限定道具「智慧灯塔」+ 100积分 | 累计邀请5人奖励 |

| **查看错题解析** | 免费 | 取消积分消耗，降低学习门槛 |

##### 4.5.2.3 概率解锁机制（核心创新）

当用户点击锁定的知识卡片时，系统根据用户当前积分和卡片解锁所需积分，触发不同的解锁流程：

**场景A：积分充足（当前积分 ≥ 所需积分）**

| 概率 | 触发机制 | 用户选择 |
|------|----------|----------|
| **30%** | 弹出"幸运解锁"提示 | ① 观看广告免积分解锁 ② 使用积分直接解锁 |
| **70%** | 直接扣除积分解锁 | 无感知，直接解锁并扣除积分 |

**场景B：积分不足（当前积分 < 所需积分）**

| 概率 | 触发机制 | 用户选择 |
|------|----------|----------|
| **100%** | 弹出"积分不足"提示 | ① 观看广告获得积分 ② 充值积分（未来功能） |

**示例流程**：

```
用户当前有150积分，点击一张需要100积分解锁的卡片：

情况1（30%概率）：
  弹出提示："🎉 幸运时刻！您可以选择："
  选项A："观看15秒广告，免费解锁此卡片"
  选项B："使用100积分直接解锁"
  用户选择A → 观看广告 → 卡片解锁（不扣积分）
  用户选择B → 扣除100积分 → 卡片解锁

情况2（70%概率）：
  直接扣除100积分
  显示："已使用100积分解锁，剩余50积分"
  卡片解锁

用户当前有50积分，点击需要100积分解锁的卡片：
  弹出提示："积分不足（50/100）"
  选项A："观看广告获得30积分"
  选项B："连续观看4次广告，立即解锁"
  用户观看广告 → 获得积分 → 积分足够后自动解锁
```

**机制设计目的**：
- **30%概率触发广告选项**：给用户"占便宜"的感觉，主动选择看广告
- **70%直接扣积分**：保证大部分情况流畅体验，不打扰用户
- **积分不足100%触发广告**：引导用户通过广告获取积分
- **选择权在用户**：不强制看广告，但看广告有明确收益

##### 4.5.2.4 积分展示与引导

- **首页显示**：当前积分余额 + "看广告获取更多积分"入口
- **卡片锁定提示**：显示所需积分 + "幸运解锁有机会免积分"
- **积分不足引导**："观看广告即可获得积分解锁"
- **积分明细**：记录积分获取/消耗明细，透明化

## 六、用户账户与认证

### 6.1 登录方式

#### 6.1.1 默认登录方式：微信授权登录

| 项目 | 说明 |
|------|------|
| **登录入口** | 首次打开小程序时自动触发 / "我的"页面点击登录 |
| **授权内容** | 微信头像、昵称、OpenID（静默授权） |
| **登录流程** | 点击登录 → 微信授权弹窗 → 获取用户信息 → 创建账户 → 登录成功 |
| **游客模式** | 未登录用户可浏览部分内容，但无法记录学习进度、积分、笔记 |
| **登录引导** | 在需要登录的功能入口（如记笔记、收藏、分享）引导用户登录 |

#### 6.1.2 补充绑定

| 绑定项 | 说明 | 奖励 |
|--------|------|------|
| **手机号绑定** | 微信一键获取手机号 / 手动输入 | +20积分（一次性） |
| **微信授权完善** | 授权获取微信头像、昵称 | 用于个人资料展示 |

#### 6.1.3 账户安全

- 用户登录态由微信维护，小程序侧通过Token鉴权
- 支持退出登录，退出后清除本地缓存的学习记录（云端保留）
- 支持账户注销，注销后数据保留30天后永久删除

## 七、商业化设计

### 5.1 盈利模式

#### 5.1.1 广告变现（主要收入来源）

| 广告类型 | 展示位置 | 触发条件 | 收益模式 |
|----------|----------|----------|----------|
| **开屏广告** | 小程序启动时 | 每次冷启动 | CPM（千次展示） |
| **激励视频广告** | 积分获取页面 | 用户主动点击"观看广告获取积分" | CPM + 激励完成 |
| **插屏广告** | 学习完成页面 | 完成一个章节学习后 | CPM |
| **Banner广告** | 笔记列表页底部 | 页面常驻 | CPM |

#### 5.1.2 积分经济体系

```
用户学习/互动 → 获得积分 → 积分不足时 → 观看广告获取积分
                      ↓
              消耗积分解锁内容 → 持续学习 → 更多积分需求
                      ↑
              直接付费购买积分（未来可扩展）
```

#### 5.1.3 广告展示策略

| 策略 | 说明 |
|------|------|
| **频次控制** | 同一用户每天最多看到5次激励视频、3次插屏广告 |
| **场景匹配** | 广告内容与教育、工具类相关，提升用户体验 |
| **去广告特权** | 未来可推出付费去广告会员服务 |
| **新手保护** | 新注册用户前3天减少广告展示频次 |

### 5.2 用户价值与商业价值的平衡

| 用户价值 | 商业价值 | 平衡策略 |
|----------|----------|----------|
| 免费学习基础内容 | 广告曝光 | 基础内容完全免费，广告不过度打扰 |
| 积分解锁进阶内容 | 激励视频广告 | 用户可选择学习积累或看广告快速获取 |
| 良好的学习体验 | 用户留存与活跃 | 广告展示时机与学习节点错开 |
| 学习成果可视化 | 分享裂变 | 分享获得积分，自然传播 |

| 指标 | 要求 |
|------|------|
| **首屏加载时间** | ≤ 2秒 |
| **页面切换响应** | ≤ 300ms |
| **知识卡片加载** | ≤ 500ms |
| **图片加载** | 支持懒加载，首屏图片优先加载 |
| **离线学习** | 支持已下载内容的离线浏览（未来版本） |

### 6.2 兼容性需求

| 维度 | 要求 |
|------|------|
| **微信版本** | 支持微信客户端 8.0 及以上版本 |
| **操作系统** | 支持 iOS 12+、Android 8+ |
| **屏幕适配** | 适配主流手机屏幕尺寸，包括全面屏 |

### 6.3 安全需求

| 维度 | 要求 |
|------|------|
| **用户数据** | 用户笔记、学习记录等数据加密存储 |
| **接口安全** | API接口采用HTTPS，关键操作需鉴权 |
| **隐私合规** | 符合微信小程序隐私规范，用户授权明确 |
| **广告合规** | 广告内容审核，禁止违规广告展示 |

### 6.4 可用性需求

| 维度 | 要求 |
|------|------|
| **新手引导** | 首次使用提供完整的新手引导流程 |
| **空状态设计** | 无数据时提供友好提示和引导操作 |
| **错误处理** | 网络异常等场景提供清晰提示和重试机制 |
| **无障碍** | 支持系统字体大小设置，重要信息不仅依赖颜色传达 |

## 七、项目规划

### 7.1 开发里程碑

| 里程碑 | 交付内容 | 验收标准 |
|--------|----------|----------|
| **M1：项目初始化** | 项目搭建、基础配置、UI框架选型 | 可运行的小程序框架，包含首页框架 |
| **M2：核心学习功能** | 知识卡片展示、学习流程、知识体系 | 可完成完整的卡片学习流程 |
| **M3：刷题系统** | 题库、答题流程、错题记录 | 支持4种题型的答题和统计 |
| **M4：笔记与记忆** | 笔记管理、复习提醒、记忆强化 | 笔记CRUD、复习计划生成 |
| **M5：积分与商业化** | 积分体系、广告接入、排行榜 | 完整的积分获取/消耗闭环 |
| **M6：优化与上线** | 性能优化、测试修复、审核上线 | 通过微信审核，正式发布 |

### 7.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 内容生产速度慢 | 上线时内容不足 | 优先完成基础篇章，采用MVP策略 |
| 用户留存率低 | 学习类产品天然流失高 | 强化提醒机制、社区功能（未来） |
| 广告收益不达预期 | 商业模式验证失败 | 控制广告频次，优先保证用户体验 |
| 微信小程序政策变化 | 功能受限或下架 | 关注平台政策，保持功能合规 |
