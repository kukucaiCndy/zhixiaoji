## 一、文档概述

### 1.1 文档目的

本文档为「知晓记」小程序运营管理后台的产品需求规格说明书，旨在为运营人员提供一套完整的内容管理、用户管理、运营配置及数据监控工具，支撑小程序的日常运营与内容迭代。

### 1.2 文档范围

本文档覆盖管理后台的全部产品定义，包括：
- 后台定位与使用场景
- 五大核心功能模块的详细需求
- 与前端小程序的功能对应关系
- 非功能需求与权限设计

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 知识体系 | 内容管理的第一层级，按学科领域或知识方向划分，如"Python入门"、"计算机基础"。用户可自由创建和命名 |
| 章节(Chapter) | 知识体系的第二层级，隶属于某个知识体系。每个章节有名称、目标、概述等属性 |
| 小节(Section) | 知识体系的第三层级，每小节对应一个具体的知识点。每小节可包含一篇完整的 HTML 图文内容页面（由 AI 工作流生成），是小程序端通过 WebView 展示的实际学习内容单元 |
| 题目/测验 | 与小节关联的互动式练习题 |
| 上架/下架 | 控制内容是否在小程序端对用户可见。上架内容只允许下架操作，下架后方可编辑或删除 |
| 删除等待状态 | 知识体系删除前需先下架；若有用户正在学习该内容，进入「删除等待」状态（1个月），期间对未学习用户不可见，仅对在学习用户可见。等待期满后强制删除 |
| AI工作流 | 后端配置的自动化内容生成流程，包括：大纲生成（工作流1）、小节内容生成（工作流2）、图片重新生成（工作流3） |
| HTML图文内容 | 由工作流2生成的完整图文页面代码，存储于后端，小程序通过 WebView 拉取展示 |
| 广告位 | 小程序内预留的微信小程序广告展示区域 |
| 页面装饰 | 小程序首页及关键页面的视觉元素配置（Banner、主题色等） |
| 文具 | 用户通过学习行为随机掉落的收集类道具，含普通/进阶/高级/传说稀有度 |
| 积分 | 用户通过观看广告、登录、测验等行为获得的虚拟货币，用于解锁内容 |
| 限定道具 | 通过特定活动（如邀请好友）获得的专属道具，无法通过常规途径获取 |
| 等级体系 | 基于学习行为和文具收集的用户成长等级系统 |

## 二、产品概述

### 2.1 产品定位

> **知晓记管理后台是面向运营人员的一站式内容管理与运营配置平台，通过可视化的操作界面，让非技术人员也能高效管理小程序的知识内容、用户数据及运营策略。**

### 2.2 核心价值主张

| 维度 | 价值描述 |
|------|----------|
| **内容管理** | 三级知识体系（知识体系→章节→小节），小节承载HTML图文内容，支持AI工作流辅助生成 |
| **课程编排** | 拖拽式章节排序，灵活调整知识体系结构 |
| **上下架控制** | 精细化内容发布管理，上架后立即生效，下架后方可编辑；支持删除等待机制 |
| **数据监控** | 实时数据看板，掌握用户行为和内容消费趋势 |
| **运营配置** | 积分规则、文具掉落、等级体系、成就系统等灵活配置 |
| **AI辅助** | 三个AI工作流（大纲生成、小节内容生成、图片重生成）串联内容生产全流程 |

#### 4.1.3 核心指标定义

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| **总用户数** | 累计注册用户总数 | 去重统计所有注册用户数 |
| **日活用户(DAU)** | 当日有学习行为的用户数 | 当日完成至少1张卡片学习或答题的用户 |
| **新增用户** | 当日新注册用户数 | 当日首次登录的用户数 |
| **今日学习** | 当日完成学习的卡片数 | 当日所有用户完成的卡片学习次数总和 |
| **内容消费率** | 用户学习内容的活跃程度 | 当日学习卡片数 / 当日活跃用户数 |
| **答题正确率** | 用户答题的整体表现 | 答对题数 / 总答题数 |
| **7日留存率** | 用户持续使用情况 | 注册7天后仍活跃的用户 / 7天前注册用户 |
| **平均学习时长** | 用户每次学习的平均时间 | 总学习时长 / 学习次数 |

#### 4.1.4 数据维度

| 维度 | 说明 |
|------|------|
| **时间维度** | 今日/昨日/近7天/近30天/自定义时间范围 |
| **用户维度** | 新用户/老用户/活跃用户/流失用户 |
| **内容维度** | 大类/章节/小节内容/题目类型 |
| **来源维度** | 自然流量/分享/搜索/广告 |

### 4.2 模块二：内容管理

#### 4.2.1 功能概述

内容管理是管理后台的核心模块，提供知识体系的构建、章节与小节的编排、小节HTML图文内容的生成与编辑、题目的创建与管理等功能。内容管理采用**三级层级模型**（知识体系 → 章节 → 小节），配合三个 AI 工作流实现从大纲到图文内容的全流程自动化生成。

**核心设计原则：**
- **上架即只读**：已上架的内容不可编辑，仅支持下架操作
- **下架方可编辑**：下架或草稿状态的内容可自由编辑和重新上架
- **删除需等待**：删除前必须先下架；若有用户正在学习，进入 30 天等待期

#### 4.2.2 页面架构总览

内容管理模块由三个核心页面层级构成：

```
┌─────────────────────────────────────────────────────────────────┐
│  L1: 内容管理页面（知识体系列表）                                 │
│  • 展示所有知识体系，按状态筛选（已上架/已下架/删除等待中）        │
│  • 已上架 → 点击进入 L2 详情页（只读）                            │
│  • 已下架/草稿 → 点击进入 L2 编辑页                               │
│  • [+ 添加知识体系] 按钮 → L2 编辑页（新建模式）                   │
└─────────────────────────────────────────────────────────────────┘
        │
        ├── 已上架知识体系 ──→ L2: 知识体系详情页（只读查看）
        │                        • 展示知识体系基本信息
        │                        • 展开章节列表，点击小节 → L3
        │                        • [下架] 按钮
        │
        └── 已下架/新建 ────→ L2: 知识体系编辑页
                                 • 编辑知识体系基本信息
                                 • 章节/小节列表（增删排序）
                                 • [AI 生成大纲] 按钮 → 工作流1
                                 • 点击小节 → L3 编辑
                                 • [保存] / [上架发布]
                                         │
                                         ▼
                              L3: 小节内容编辑预览页
                              • 预览/编辑 HTML 图文内容
                              • [生成内容] → 工作流2
                              • [重新生成图片] → 工作流3
                              • [保存] 生效
```

##### 4.2.3.6 AI 工作流集成

内容管理模块深度集成三个 AI 工作流，形成完整的内容生产流水线。

###### 工作流1：大纲生成

| 项目 | 说明 |
|------|------|
| **触发位置** | L2 编辑页 [AI 生成大纲] 按钮 |
| **输入** | 知识体系名称（如 "Python入门"） |

##### 4.2.3.7 删除流程

知识体系的删除遵循严格的状态流转规则。

###### 删除状态机

```
          ┌──→ 草稿 ──→ 手动删除（立即生效）
          │
已上架 ──→ 已下架 ──→ 确认删除
                        │
                        ├── 无用户学习中 ──→ 直接删除
                        │
                        └── 有用户学习中 ──→ 进入「删除等待中」状态
                                                │
                                                ├── 对未学习用户：不可见
                                                ├── 对在学习用户：可见（可继续学完）
                                                │
                                                └── 30天后 ──→ 强制删除（不管是否学完）
```

###### 删除规则详述

| 规则 | 说明 |
|------|------|
| **前置条件** | 必须先下架，才能触发删除操作 |
| **无用户学习中** | 确认删除后立即生效，数据从数据库移除 |
| **有用户学习中** | 确认删除后进入「删除等待中」状态，不立即删除数据 |
| **等待期可见性** | 对未开始学习的用户完全不可见；对正在学习该内容的用户仍然可见，允许继续学完 |
| **等待期时长** | 30 天（自然日） |
| **等待期满** | 自动强制删除，不再保留任何数据 |
| **手动撤销** | 在等待期内，运营人员可将状态恢复为「已下架」，取消删除 |
| **删除确认** | 删除操作需二次弹窗确认，提示删除影响范围（涉及章节数、小节数、在学习用户数） |

#### 4.4.4 子模块三：积分规则

##### 4.4.4.1 功能描述

配置小程序积分体系的获取规则和消耗规则。积分仅用于解锁知识内容，学习行为不再直接产生积分，避免功利化学习。

##### 4.4.4.2 积分获取规则

| 行为 | 默认积分 | 每日上限 | 可配置参数 |
|------|----------|----------|------------|
| **每日登录** | 10 | 10积分 | 积分数值 |
| **章节测验通过** | 20 | 60积分 | 积分数值、正确率要求 |
| **每日挑战完成** | 15 | 15积分 | 积分数值 |
| **连续打卡7天** | 50 | 50积分 | 积分数值、连续天数要求 |
| **观看激励视频广告** | 30 | 150积分（5次） | 积分数值、每日次数上限 |
| **邀请新用户** | 100 | 500积分 | 积分数值、被邀请人需完成首次学习 |

> **设计原则**：
> - 积分可通过**登录**和**学习考核**获得，鼓励持续学习
> - 观看广告获得积分效率更高，为愿意看广告的用户提供捷径
> - 移除"完成卡片学习"积分奖励，避免用户为刷积分而快速浏览

##### 4.4.4.3 积分消耗规则

| 行为 | 默认积分 | 可配置参数 |
|------|----------|------------|
| **解锁小节内容** | 50-150 | 积分数值、目标小节 |
| **解锁进阶章节** | 200-500 | 积分数值、目标章节 |
| **解锁实战项目** | 800-1500 | 积分数值、目标项目 |
| **解锁专项课程** | 500-1000 | 积分数值、目标课程 |
| **去广告特权** | 500/7天 | 积分数值、特权时长 |

> **变更说明**：移除"积分兑换实物/虚拟商品"功能，积分仅用于解锁内容。实物/虚拟商品兑换移至文具系统。

##### 4.4.4.4 概率解锁机制配置

| 配置项 | 默认值 | 可配置范围 | 说明 |
|--------|--------|------------|------|
| **幸运解锁概率** | 30% | 0-100% | 积分充足时触发"观看广告免积分解锁"的概率 |
| **直接扣积分概率** | 70% | 0-100% | 积分充足时直接扣除积分解锁的概率 |
| **积分不足广告选项** | 开启 | 开启/关闭 | 积分不足时是否提供"观看广告获取积分"选项 |

##### 4.4.4.5 功能详述

| 功能 | 说明 |
|------|------|
| **规则编辑** | 修改各行为的积分数值、上限、条件 |
| **规则开关** | 启用/禁用某项积分规则 |
| **积分流水查询** | 查看所有用户的积分获取/消耗记录 |
| **积分调整** | 对特定用户进行积分补发或扣除（需填写原因） |
| **概率解锁配置** | 调整幸运解锁概率、积分不足时的引导策略 |

## 五、非功能需求

### 5.1 性能需求

| 指标 | 要求 |
|------|------|
| **页面加载时间** | 首屏加载不超过3秒，后续页面切换不超过1秒 |
| **数据查询响应** | 常规列表查询不超过500ms，复杂统计查询不超过3秒 |
| **并发支持** | 支持10个运营人员同时在线操作 |
| **数据导出** | 万级数据导出不超过30秒 |
| **编辑器响应** | 富文本编辑器输入延迟不超过100ms |

### 5.2 兼容性需求

| 项目 | 要求 |
|------|------|
| **浏览器** | 支持Chrome 90+、Firefox 88+、Edge 90+、Safari 14+ |
| **分辨率** | 适配1366x768及以上分辨率，推荐1920x1080 |
| **移动端适配** | 核心功能支持平板设备访问，不推荐手机端使用 |

### 5.3 安全需求

| 项目 | 要求 |
|------|------|
| **登录安全** | 账号密码登录，密码加密存储，支持登录失败锁定 |
| **操作鉴权** | 所有接口需校验登录状态，防止未授权访问 |
| **数据安全** | 用户敏感信息脱敏展示，导出数据自动脱敏 |
| **XSS防护** | 富文本编辑器内容需过滤危险标签和脚本 |
| **CSRF防护** | 接口请求需携带Token验证 |
| **操作审计** | 所有写操作记录完整日志 |

### 5.4 可用性需求

| 项目 | 要求 |
|------|------|
| **系统可用性** | 99.9%（月度停机时间不超过43分钟） |
| **数据备份** | 每日自动全量备份，保留最近30天备份 |
| **灾难恢复** | RPO（恢复点目标）不超过1小时，RTO（恢复时间目标）不超过4小时 |
