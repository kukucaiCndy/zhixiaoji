## 一、文档概述

### 1.1 文档目的

本文档为「知晓记」小程序运营管理后台的产品需求规格说明书，旨在为运营人员提供一套完整的内容管理、用户管理、运营配置及数据监控工具，支撑小程序的日常运营与内容迭代。

### 1.2 文档范围

本文档覆盖管理后台的全部产品定义，包括：
- 后台定位与使用场景
- 五大核心功能模块的详细需求
- 与前端小程序的功能对应关系
- 非功能需求与权限设计

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 知识卡片 | 小程序端展示的最小学习单元，包含概念解释、生活类比、代码示例等 |
| 大类(Category) | 知识体系第一层级，按学科领域或知识方向划分，如"计算机基础知识"、"Web开发基础" |
| 章节(Chapter) | 知识体系第二层级，隶属于某个大类，如"计算机基础知识"下有 10 个章节 |
| 小节内容(Section) | 知识体系第三层级，每个章节下包含若干小节，每小节对应一篇富文本图文内容，类似微信公众号图文文章 |
| 题目/测验 | 与知识卡片关联的互动式练习题 |
| 上架/下架 | 控制内容是否在小程序端对用户可见 |
| 广告位 | 小程序内预留的微信小程序广告展示区域 |
| 页面装饰 | 小程序首页及关键页面的视觉元素配置（Banner、主题色等） |
| 文具 | 用户通过学习行为随机掉落的收集类道具，含普通/进阶/高级/传说稀有度 |
| 积分 | 用户通过观看广告、登录、测验等行为获得的虚拟货币，用于解锁内容 |
| 限定道具 | 通过特定活动（如邀请好友）获得的专属道具，无法通过常规途径获取 |
| 等级体系 | 基于学习行为和文具收集的用户成长等级系统 |

## 二、产品概述

### 2.1 产品定位

> **知晓记管理后台是面向运营人员的一站式内容管理与运营配置平台，通过可视化的操作界面，让非技术人员也能高效管理小程序的知识内容、用户数据及运营策略。**

### 2.2 核心价值主张

| 维度 | 价值描述 |
|------|----------|
| **内容管理** | 可视化编辑器快速创建知识卡片，支持富文本、代码高亮、图片上传 |
| **课程编排** | 拖拽式章节排序，灵活调整知识体系结构 |
| **上下架控制** | 精细化内容发布管理，上架后立即生效，支持批量操作 |
| **数据监控** | 实时数据看板，掌握用户行为和内容消费趋势 |
| **运营配置** | 积分规则、文具掉落、等级体系、成就系统等灵活配置 |
| **AI辅助** | AI工作流辅助生成知识卡片和题目内容，提升内容生产效率 |

## 四、核心功能模块

### 4.1 模块一：数据看板

#### 4.1.1 功能概述

为运营人员提供小程序核心数据的实时监控与多维度分析，支持快速了解产品运行状态、用户行为趋势及内容消费情况。

#### 4.1.2 页面布局

```
┌─────────────────────────────────────────────────────────────┐
│  数据看板                                                    │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│  │ 总用户数 │ │ 日活用户 │ │ 新增用户 │ │ 今日学习 │          │
│  │ 12,580  │ │  2,340  │ │   156   │ │  1,892  │          │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘          │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────┐ ┌─────────────────────────┐   │
│  │     用户增长趋势         │ │     活跃用户留存         │   │
│  │      [折线图]            │ │      [留存表格]          │   │
│  └─────────────────────────┘ └─────────────────────────┘   │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────┐ ┌─────────────────────────┐   │
│  │     内容消费数据         │ │     学习转化漏斗         │   │
│  │   [卡片学习/刷题统计]     │ │   [曝光→学习→完成→测验]  │   │
│  └─────────────────────────┘ └─────────────────────────┘   │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────────────────┐   │
│  │              热门内容排行TOP10                        │   │
│  │         [知识卡片/篇章/题目 学习量排行]                │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

#### 4.1.3 核心指标定义

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| **总用户数** | 累计注册用户总数 | 去重统计所有注册用户数 |
| **日活用户(DAU)** | 当日有学习行为的用户数 | 当日完成至少1张卡片学习或答题的用户 |
| **新增用户** | 当日新注册用户数 | 当日首次登录的用户数 |
| **今日学习** | 当日完成学习的卡片数 | 当日所有用户完成的卡片学习次数总和 |
| **内容消费率** | 用户学习内容的活跃程度 | 当日学习卡片数 / 当日活跃用户数 |
| **答题正确率** | 用户答题的整体表现 | 答对题数 / 总答题数 |
| **7日留存率** | 用户持续使用情况 | 注册7天后仍活跃的用户 / 7天前注册用户 |
| **平均学习时长** | 用户每次学习的平均时间 | 总学习时长 / 学习次数 |

#### 4.1.4 数据维度

| 维度 | 说明 |
|------|------|
| **时间维度** | 今日/昨日/近7天/近30天/自定义时间范围 |
| **用户维度** | 新用户/老用户/活跃用户/流失用户 |
| **内容维度** | 篇章/章节/知识卡片/题目类型 |
| **来源维度** | 自然流量/分享/搜索/广告 |

### 4.2 模块二：内容管理

#### 4.2.1 功能概述

提供知识体系的构建、知识卡片的创建与编辑、题目管理、AI内容生成等功能，是管理后台的核心模块。

#### 4.2.2 子模块一：知识体系

##### 4.2.2.1 功能描述

管理小程序的知识体系结构，包括篇章（大章节）和章节（小章节）的创建、编辑、排序和上下架。

##### 4.2.2.2 功能详述

| 功能 | 说明 |
|------|------|
| **篇章管理** | 创建/编辑/删除篇章，设置篇章名称、排序、状态 |
| **章节管理** | 在篇章下创建/编辑/删除章节，设置章节属性 |
| **拖拽排序** | 支持篇章和章节的拖拽排序，实时调整展示顺序 |
| **上下架控制** | 控制篇章/章节是否在小程序端展示 |
| **前置依赖** | 设置章节解锁的前置条件（如需完成某章节） |
| **难度标记** | 为章节设置难度标签（入门/基础/进阶） |

##### 4.2.2.3 章节属性

| 属性 | 说明 | 必填 |
|------|------|------|
| **章节名称** | 章节标题 | 是 |
| **所属篇章** | 关联的父级篇章 | 是 |
| **排序序号** | 展示顺序 | 是 |
| **难度** | 入门/基础/进阶 | 是 |
| **前置章节** | 解锁本章节需完成的前置章节 | 否 |
| **积分解锁** | 是否需消耗积分解锁 | 否 |
| **所需积分** | 解锁所需积分（如需） | 否 |
| **状态** | 上架/下架 | 是 |

#### 4.2.3 子模块二：知识卡片

##### 4.2.3.1 功能描述

创建和管理知识卡片，支持富文本编辑、代码高亮、图片上传等功能。

##### 4.2.3.2 卡片内容结构

| 元素 | 说明 | 必填 |
|------|------|------|
| **卡片标题** | 知识点名称 | 是 |
| **所属章节** | 关联的章节 | 是 |
| **难度标签** | 入门/基础/进阶 | 是 |
| **预计时长** | 建议学习时间（分钟） | 是 |
| **概念解释** | 通俗语言解释概念 | 是 |
| **生活类比** | 日常生活场景类比 | 是 |
| **代码示例** | 代码片段（支持语法高亮） | 否 |
| **图解说明** | 图片/示意图 | 否 |
| **要点总结** | 3-5个核心要点 | 是 |
| **互动提问** | 引导思考的问题 | 否 |
| **状态** | 上架/下架/草稿 | 是 |

##### 4.2.3.3 富文本编辑器

| 功能 | 说明 |
|------|------|
| **基础样式** | 标题、加粗、斜体、引用、列表 |
| **代码块** | 支持多种编程语言语法高亮，行号显示 |
| **图片上传** | 支持本地上传、拖拽上传、粘贴上传 |
| **表格** | 支持插入和编辑表格 |
| **公式** | 支持LaTeX数学公式（V2.0） |
| **预览模式** | 实时预览小程序端展示效果 |
| **自动保存** | 编辑内容每30秒自动保存草稿 |

#### 4.2.4 子模块三：题目管理

##### 4.2.4.1 功能描述

管理小程序的题库，支持单选题、多选题、判断题的创建、编辑和与知识卡片的关联。

##### 4.2.4.2 题目类型

| 类型 | 说明 | 选项要求 |
|------|------|----------|
| **单选题** | 4个选项，选择唯一正确答案 | 4个选项，1个正确答案 |
| **多选题** | 4个选项，选择2-3个正确答案 | 4个选项，2-3个正确答案 |
| **判断题** | 判断陈述是否正确 | 是/否两个选项 |

##### 4.2.4.3 题目信息结构

| 字段 | 说明 | 必填 |
|------|------|------|
| **题目内容** | 题目描述 | 是 |
| **题目类型** | 单选/多选/判断 | 是 |
| **选项** | 选项内容（A/B/C/D） | 是 |
| **正确答案** | 正确选项标识 | 是 |
| **答案解析** | 详细解析说明 | 是 |
| **关联卡片** | 关联的知识卡片 | 是 |
| **难度** | 入门/基础/进阶 | 是 |
| **状态** | 上架/下架 | 是 |

##### 4.2.4.4 功能详述

| 功能 | 说明 |
|------|------|
| **新增题目** | 填写题目信息，设置选项和正确答案 |
| **编辑题目** | 修改题目内容、选项、解析等 |
| **批量导入** | 通过Excel模板批量导入题目 |
| **批量导出** | 导出题目为Excel，支持筛选条件 |
| **关联卡片** | 将题目与知识卡片关联，支持一题多卡 |
| **题目查重** | 检测重复或高度相似的题目 |
| **难度调整** | 根据答题数据统计自动建议难度调整 |

#### 4.2.5 子模块四：AI内容生成

##### 4.2.5.1 功能描述

利用AI工作流辅助生成知识卡片和题目内容，提升内容生产效率。运营人员输入知识点主题和关键要求，AI自动生成内容草稿，经人工审核确认后发布。

##### 4.2.5.2 AI生成内容类型

| 内容类型 | 生成内容 | 人工审核要点 |
|----------|----------|--------------|
| **知识卡片** | 概念解释、生活类比、要点总结、互动提问 | 准确性、通俗性、类比恰当性 |
| **代码示例** | 与知识点匹配的代码片段 | 语法正确性、可运行性 |
| **练习题** | 单选题/多选题/判断题及解析 | 题目准确性、选项迷惑性 |
| **图解说明** | AI生成示意图描述（需人工配图或AI绘图） | 图示准确性 |

##### 4.2.5.3 AI生成流程

```
运营人员输入
    │
    ├── 知识点主题
    ├── 目标难度（入门/基础/进阶）
    ├── 内容类型（卡片/题目/代码）
    └── 特殊要求（可选）
            │
            ▼
    ┌─────────────────┐
    │   AI内容生成     │  ← 调用AI接口，生成内容草稿
    │  （10-30秒）      │
    └─────────────────┘
            │
            ▼
    运营人员审核编辑
            │
            ├── 满意 ──→ 保存为草稿/直接发布
            │
            └── 不满意 ──→ 调整要求重新生成
```

##### 4.2.5.4 功能详述

| 功能 | 说明 |
|------|------|
| **AI生成入口** | 在知识卡片/题目编辑页面提供"AI辅助生成"按钮 |
| **生成参数** | 设置生成主题、难度、内容类型、字数限制等 |
| **生成历史** | 查看历史生成记录，支持重新生成和复用 |
| **人工审核** | AI生成内容默认保存为草稿，需人工审核后发布 |
| **质量反馈** | 对AI生成内容打分，反馈用于优化模型 |
| **批量生成** | 基于章节大纲批量生成多张知识卡片（V2.0） |

#### 4.2.6 上下架控制

##### 4.2.6.1 功能描述

控制知识内容（篇章、章节、卡片、题目）的发布状态，上架后小程序端立即可见。

##### 4.2.6.2 状态流转

```
草稿 ──→ 已上架 ──→ 已下架
  │        │
  │        └──→ 编辑后变为草稿（需重新上架）
  │
  └──→ 可直接删除
```

##### 4.2.6.3 功能详述

| 功能 | 说明 |
|------|------|
| **单条上下架** | 对单个内容进行上架/下架操作 |
| **批量上下架** | 选择多个内容进行批量操作 |
| **定时上架** | 设置未来时间自动上架 |
| **上架检查** | 上架前检查内容完整性（必填项、关联关系） |
| **版本管理** | 记录内容修改历史，支持查看历史版本 |
| **即时生效** | 上架后小程序端无需发版立即生效 |

### 4.3 模块三：用户管理

#### 4.3.1 功能概述

管理小程序用户数据，包括用户列表、用户详情、笔记管理、学习记录查看、积分记录查询等。

#### 4.3.2 子模块一：用户列表

##### 4.3.2.1 功能描述

查看和管理所有注册用户的基本信息和行为数据。

##### 4.3.2.2 用户列表字段

| 字段 | 说明 |
|------|------|
| **用户ID** | 系统唯一标识 |
| **微信头像** | 用户微信头像 |
| **微信昵称** | 用户微信昵称 |
| **注册时间** | 首次登录时间 |
| **最后活跃** | 最近一次活跃时间 |
| **学习卡片数** | 累计完成学习的卡片数 |
| **当前等级** | 用户当前等级 |

#### 4.4.4 子模块三：积分规则

##### 4.4.4.1 功能描述

配置小程序积分体系的获取规则和消耗规则。积分仅用于解锁知识内容，学习行为不再直接产生积分，避免功利化学习。

##### 4.4.4.2 积分获取规则

| 行为 | 默认积分 | 每日上限 | 可配置参数 |
|------|----------|----------|------------|
| **每日登录** | 10 | 10积分 | 积分数值 |
| **章节测验通过** | 20 | 60积分 | 积分数值、正确率要求 |
| **每日挑战完成** | 15 | 15积分 | 积分数值 |
| **连续打卡7天** | 50 | 50积分 | 积分数值、连续天数要求 |
| **观看激励视频广告** | 30 | 150积分（5次） | 积分数值、每日次数上限 |
| **邀请新用户** | 100 | 500积分 | 积分数值、被邀请人需完成首次学习 |

> **设计原则**：
> - 积分可通过**登录**和**学习考核**获得，鼓励持续学习
> - 观看广告获得积分效率更高，为愿意看广告的用户提供捷径
> - 移除"完成卡片学习"积分奖励，避免用户为刷积分而快速浏览

##### 4.4.4.3 积分消耗规则

| 行为 | 默认积分 | 可配置参数 |
|------|----------|------------|
| **解锁知识卡片** | 50-150 | 积分数值、目标卡片 |
| **解锁进阶章节** | 200-500 | 积分数值、目标章节 |
| **解锁实战项目** | 800-1500 | 积分数值、目标项目 |
| **解锁专项课程** | 500-1000 | 积分数值、目标课程 |
| **去广告特权** | 500/7天 | 积分数值、特权时长 |

> **变更说明**：移除"积分兑换实物/虚拟商品"功能，积分仅用于解锁内容。实物/虚拟商品兑换移至文具系统。

##### 4.4.4.4 概率解锁机制配置

## 五、非功能需求

### 5.1 性能需求

| 指标 | 要求 |
|------|------|
| **页面加载时间** | 首屏加载不超过3秒，后续页面切换不超过1秒 |
| **数据查询响应** | 常规列表查询不超过500ms，复杂统计查询不超过3秒 |
| **并发支持** | 支持10个运营人员同时在线操作 |
| **数据导出** | 万级数据导出不超过30秒 |
| **编辑器响应** | 富文本编辑器输入延迟不超过100ms |

### 5.2 兼容性需求

| 项目 | 要求 |
|------|------|
| **浏览器** | 支持Chrome 90+、Firefox 88+、Edge 90+、Safari 14+ |
| **分辨率** | 适配1366x768及以上分辨率，推荐1920x1080 |
| **移动端适配** | 核心功能支持平板设备访问，不推荐手机端使用 |

### 5.3 安全需求

| 项目 | 要求 |
|------|------|
| **登录安全** | 账号密码登录，密码加密存储，支持登录失败锁定 |
| **操作鉴权** | 所有接口需校验登录状态，防止未授权访问 |
| **数据安全** | 用户敏感信息脱敏展示，导出数据自动脱敏 |
| **XSS防护** | 富文本编辑器内容需过滤危险标签和脚本 |
| **CSRF防护** | 接口请求需携带Token验证 |
| **操作审计** | 所有写操作记录完整日志 |

### 5.4 可用性需求

| 项目 | 要求 |
|------|------|
| **系统可用性** | 99.9%（月度停机时间不超过43分钟） |
| **数据备份** | 每日自动全量备份，保留最近30天备份 |
| **灾难恢复** | RPO（恢复点目标）不超过1小时，RTO（恢复时间目标）不超过4小时 |

### 8.2 数据模型概要

#### 8.2.1 知识体系
- `knowledge_volume`（篇章表）: id, name, sort_order, status, created_at, updated_at
- `knowledge_chapter`（章节表）: id, volume_id, name, sort_order, difficulty, status, created_at, updated_at

#### 8.2.2 知识内容
- `knowledge_card`（知识卡片表）: id, chapter_id, title, difficulty, duration, content_json, summary_points, status, created_at, updated_at
- `question`（题目表）: id, type, chapter_id, content, options, answer, explanation, difficulty, status, created_at, updated_at
- `question_card_relation`（题目卡片关联表）: id, question_id, card_id

#### 8.2.3 用户数据
- `user`（用户表）: id, openid, nickname, avatar, level, status, created_at, last_active_at
- `user_learning_record`（学习记录表）: id, user_id, card_id, action_type, created_at
- `user_note`（笔记表）: id, user_id, card_id, title, content, status, created_at, updated_at
- `user_points_record`（积分记录表）: id, user_id, action, points, balance, created_at
- `user_stationery`（用户文具表）: id, user_id, stationery_id, quantity, created_at, updated_at
- `user_level_record`（用户等级记录表）: id, user_id, level, upgrade_time, created_at

#### 8.2.4 运营配置
- `ad_position`（广告位表）: id, name, type, config_json, status, created_at, updated_at
- `banner`（Banner表）: id, image_url, target_type, target_id, sort_order, status, created_at, updated_at
- `points_rule`（积分规则表）: id, action, points, daily_limit, config_json, status
- `stationery`（文具定义表）: id, name, icon, rarity, category, story, usage, status, created_at, updated_at
- `stationery_drop_rule`（文具掉落规则表）: id, action, rarity, probability, guarantee_count, guarantee_rarity, status
- `stationery_compose_rule`（文具合成规则表）: id, source_rarity, target_rarity, ratio, status
- `stationery_privilege`（文具特权表）: id, name, required_stationery, required_count, effect, duration, status
- `level_config`（等级配置表）: id, level, title, condition_json, privilege_json, icon, status
- `achievement`（成就表）: id, name, description, icon, condition_type, condition_value, reward_stationery_id, reward_count, status
- `leaderboard_config`（排行榜配置表）: id, type, rule, period, top_n, status
- `limited_item`（限定道具表）: id, name, rarity, type, effect, invite_milestone, status
- `review_rule`（复习规则表）: id, review_times, interval_days, config_json
- `ai_generate_record`（AI生成记录表）: id, operator, generate_type, params, result, status, created_at
